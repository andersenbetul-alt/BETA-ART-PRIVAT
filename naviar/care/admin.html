How form requests work
Booking requests → email
NaviarCare is a static site with no server. When a visitor submits the booking form on booking.html, it opens their email client with a pre-filled draft — name, language, preferred doctor, and their message. The email goes to the address set in assets/js/config.js (currently pilot@naviarcare.example).
To change the intake address: edit assets/js/config.js → contactEmail → commit and deploy.
Doctor join applications → email
The "For doctors" form on join.html works the same way — opens a mailto: draft. To add a separate intake address for doctor applications, update config.js → doctorEmail (field exists but defaults to contactEmail).
Symptom checks → stored client-side only
Triage entries (symptom checker on triage.html) are processed in the browser and never sent to a server. Nothing is stored. If you need to collect triage data, you will need a backend integration (Vercel Functions, Supabase, or similar).
Moving to a real backend
When you are ready to replace the mailto: flow with a real form submission, the change point is the composeMail() function in assets/js/app.js. Replace the mailto: href construction with a fetch() POST to your chosen endpoint and update vercel.json → Content-Security-Policy → connect-src to allow that host.
